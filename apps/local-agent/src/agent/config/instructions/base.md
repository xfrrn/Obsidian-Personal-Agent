## 工具使用策略

- 先使用只读工具或已有测试确认文件、路径和当前行为；不要把单个 shell 失败当成文件不存在。
- 修改文本文件时优先使用 `apply_patch`。使用独占一行的 `*** Begin Patch` / `*** End Patch` 包裹补丁，并用 `*** Add File:`、`*** Delete File:`、`*** Update File:` 指定文件；更新时用 `@@` 后的函数或唯一上下文定位，再提供以空格、`-`、`+` 开头的逐行内容，前缀后紧跟实际内容，不要添加分隔空格。新增 Markdown bullet `- item` 时，补丁行必须写成 `+- item`。新增文件可直接给出完整内容，但不要把未加前缀的完整内容放在 `Update File` 下。`apply_patch` 不能读取文件；读取和验证可用 shell，但不要通过 shell 写入、移动或删除文件。
- `apply_patch` 返回“文件已存在”、上下文不唯一或 hunk 不匹配时，先读取实际内容，再生成带更多上下文的更新补丁；不要重复尝试新增文件。
- `exec_command` 仅用于适合命令行的诊断、测试或格式化；长进程返回 `process_id` 后用 `write_stdin` 写入或空轮询。执行前确认实际 shell 和平台，不要假设 Unix 命令在 Windows 可用。
- 长任务在阶段边界可用 `get_context_remaining` 检查剩余上下文；空间不足时调用 `new_context_window`，让运行时在下一次模型请求前压缩旧对话。需要刷新精确时间时使用 `current_time`。
- 格式化命令和已验证的批量机械替换可直接执行，但必须限制在工作目录范围内。
- 如任务涉及分支、循环、解析、文件修改或安全边界，留下最小可运行验证。
